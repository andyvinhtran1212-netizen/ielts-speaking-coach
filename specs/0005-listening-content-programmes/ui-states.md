# UI state matrix

| Surface | Loading | Empty | Success | Error/retry | Permission | Responsive/theme/a11y |
| --- | --- | --- | --- | --- | --- | --- |
| `/listening` hub | Skeleton/state placeholders use `…`; no invented zero counts | If neither programme has public forms, explain that content is being prepared and keep existing eligible libraries reachable | One resume/next card, two programme cards, bounded recent activity, progress, and secondary Browse/Analytics links | If one aggregate fails, keep settled independent sections and label the unavailable block; retry refetches canonical data | Existing authenticated gate; no learner data before sign-in | Canonical shell; stacked programme cards on mobile; light/dark; visible focus; 44px targets; reduced motion |
| Resume card | Reserve one card-sized region while eligibility loads | No active eligible free-practice attempt -> show one deterministic next action, not a blank card | Show programme, lesson/form, saved progress, expiry context, and one `Tiếp tục` action | Expired/stale attempt disappears after canonical refetch; never link to sealed mock/class context | Attempt ownership remains server-enforced | Focus lands on one primary action; text wraps at 375px; status is not color-only |
| General library | Lesson-card skeletons and filter controls remain stable | Explain no published General forms or no results for the selected filter; offer reset/back | 56 lesson/group cards at full release, with progress and one primary action | Keep filters and show retry; never present failed count lookup as zero completion | Authenticated published content only | No horizontal scroll; filters wrap/collapse; cards use semantic tokens and sentence case |
| General lesson detail | Form placeholders do not expose protected fields | Lesson with no public forms shows truthful unavailable state | Forms show purpose, duration, item mix, replay/support policy, progress, and start/continue | Missing derived media or invalid form is blocked with friendly retry/back guidance | Transcript accommodation/post-submit access remains server-authorized | Heading hierarchy, keyboard form order, screen-reader labels, both themes |
| IELTS hub | Mode cards use loading placeholders for counts | Imported practice may be empty while existing Quick/Skills/Mini/Full links remain available | Imported IELTS Practice is visibly report-only and separate from exam modes | One mode failure does not hide other working modes; retry is section-scoped | Existing auth and public visibility rules | Commitment-order layout stacks cleanly; result contract is conveyed by text plus badge |
| Report-only form player | Audio and item shell load without answer/transcript leakage | Invalid or unpublished form cannot start and offers a safe return | Autosave/resume, policy-correct replay, one-to-fifteen stimulus timeline, and all response renderers work | Audio failure exposes retry; save ambiguity keeps local pending truth and never fabricates completion | Signed/authorized media only; controlled transcript withheld by default | Existing exam-paper exception where applicable; keyboard inputs, accessible audio controls, 44px actions |
| Mixed report-only result | Submission state remains pending until canonical finalization | A form with no auto-checked items still renders completion plus self-review | Separate `Đã kiểm tra`, `Tự đối chiếu`, blank, and technical-error counts; no band/CEFR/mastery/pass | Failed result read keeps submitted state and offers retry; reload matches canonical result | Only attempt owner can read answers/result | Status uses icon/text, not color alone; long rubric text remains readable in both themes |
| Analytics | Preserve range controls and show non-zero placeholders only after data loads | Explain no activity for selected window | Diagnostic score/weakness and report-only completion appear as separate sections | Partial diagnostic or completion failure is explicitly labeled; retry is available | Existing learner ownership | Mobile table/card transformation preserves labels; focus and contrast pass |

Canonical backend state owns visibility, progress, resume eligibility, scoring policy,
and result status. The frontend must not infer a band, CEFR level, mastery state,
weakness, completed attempt, or absent content from missing/failed data.
